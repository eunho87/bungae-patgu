# 번개팟구

2026-2학기 AI개발과실전 1조 프로젝트. 숭실대학교 학생이 즉흥적으로 함께할 사람을 찾을 수 있게 돕는 교내 번개 모임 웹서비스다. 실행과 배포 절차는 `실행방법.md`에, 노션 보고서에 옮겨 적을 내용은 `docs/노션_작성자료.md`에 따로 정리했다.

## 1. 무엇을 해결하려고 했나

갑자기 시간이 비었을 때 같이 밥을 먹거나 보드게임을 할 사람을 구하려면 지인에게 하나씩 연락하거나 단체 채팅방과 게시판을 뒤져야 한다. 지금 참여할 수 있는 모임이 무엇인지, 몇 시에 어디서 몇 명이 모이는지 한눈에 보이지 않는다는 점이 문제였다. 번개팟구는 모임을 여는 일과 찾는 일을 한곳에 모으고, "지금 2시간 비는데 뭐 하지?"라고 물으면 열려 있는 모임 가운데 맞는 것을 골라 주는 것을 목표로 했다.

## 2. 할 수 있는 일

모임을 여는 사람(호스트)은 모임 이름, 활동 종류, 날짜와 시간, 예상 소요 시간, 장소, 모집 인원, 분위기 태그, 소개를 입력해 번개를 연다. 참여자끼리 연락할 오픈채팅 링크도 넣을 수 있는데, 이 링크는 참여가 확정된 사람에게만 보인다. 호스트는 참여자 목록을 확인하고, 모집을 직접 마감하거나 다시 열 수 있으며, 모임을 취소할 수 있다.

참여하려는 사람은 홈 화면에서 열려 있는 모임을 보고, 검색어·활동 종류·날짜·시간대·참여 가능 여부로 걸러 본다. 모임 상세 화면에서 모집 현황을 확인하고 참여 버튼을 누르면 선착순으로 바로 확정된다. 정원이 차면 자동으로 마감되고, 누군가 취소하면 자리가 다시 열린다. 모임 시작 시각이 지나면 모집은 자동으로 끝난다. 참여 전에 궁금한 점은 댓글로 물어볼 수 있다.

추천은 두 군데에서 이루어진다. 홈 화면에는 가입할 때 고른 관심사에 맞는 모임이 "나를 위한 추천"으로 올라오고, 추천 탭의 챗봇은 문장으로 받은 조건에 맞는 모임을 골라 준다. 맞는 모임이 없으면 조건을 조금 푼 대안을 보여 주고, 그 조건 그대로 직접 번개를 여는 버튼을 함께 낸다.

그 밖에 유명 모임 서비스들이 공통으로 갖춘 기능 가운데 구현 부담이 작고 쓸모가 분명한 것을 골라 넣었다. 이미 참여 중인 모임과 시간이 겹치면 경고하고 추천에서도 빼 주는 기능, 한 자리만 남았거나 곧 시작하는 모임에 붙는 마감 임박 표시, 같은 종류의 비슷한 모임 보여 주기, 호스트가 지금까지 모임을 몇 번 열고 참여했는지 보여 주는 활동 기록, 모임 링크 공유, 구글 캘린더에 일정 추가가 그것이다.

푸시 알림을 보낼 수단이 없는 대신 사이트 안 알림함을 두었다. 누가 내 번개에 참여하거나 취소하거나 댓글을 남기면, 또는 참여한 번개의 시간·장소가 바뀌거나 취소되면 화면 위 종 아이콘에 숫자가 뜬다. 두 시간 안에 시작하는 내 번개는 홈 맨 위에 따로 알려 준다.

안전을 위한 최소 장치로 모임 신고를 넣었다. 운영자가 상주하지 않으므로 서로 다른 세 사람의 신고가 쌓이면 모집이 자동으로 멈추고 호스트가 다시 열 수 없다. 가입할 때는 저장하는 정보를 안내하고 동의를 받으며, 비밀번호 변경과 회원 탈퇴를 할 수 있다. 탈퇴하면 계정과 그 사람이 남긴 모임·참여 기록·댓글·알림을 지운다.

번개를 여는 과정은 타이핑 없이 끝낼 수 있게 줄였다. 시작 시간은 '30분 뒤'가 미리 들어가 있고 '1시간 뒤', '오늘 저녁 6시' 같은 버튼으로 바꿀 수 있다. 장소도 자주 쓰는 곳을 버튼으로 고른다. 모임 이름을 비워 두면 '공부 번개 · 중앙도서관'처럼 종류와 장소로 지어 준다. 찾는 쪽에서는 홈의 '2시간 안에 시작', '참여 가능만' 버튼으로 지금 갈 수 있는 모임만 바로 추릴 수 있다.

## 3. 구조

언어는 Python이고 웹 프레임워크는 Flask다. 화면은 서버에서 HTML을 만들어 내려보내는 방식이며, 챗봇 화면만 JavaScript로 서버 API를 호출한다. 데이터는 SQLAlchemy를 거쳐 저장하므로 같은 코드가 로컬에서는 SQLite 파일을, 배포 환경에서는 PostgreSQL을 쓴다.

폴더는 조원 역할 분담과 같은 경계로 나눴다.

- `bungae/templates/`, `public/assets/` : 화면 구성과 사용자 인터페이스
- `bungae/meetings.py`, `bungae/auth.py`, `bungae/account.py`, `bungae/notify.py` : 모임 생성·참여·신고, 회원가입·로그인, 계정 설정, 알림
- `bungae/discover.py`, `bungae/recommend.py`, `bungae/nlu.py`, `bungae/llm.py`, `bungae/chatbot.py` : 목록·검색, 추천, 챗봇
- `tests/`, `seed.py`, `bungae/demo.py` : 테스트와 시연용 데이터
- `bungae/models.py`, `bungae/timeutil.py` : 여러 기능이 함께 쓰는 데이터 구조와 시간 처리

데이터는 사용자, 모임, 참여, 댓글 네 가지가 중심이고 알림과 신고가 여기에 딸려 있다. 모임의 상태는 호스트의 의사(열림, 직접 마감, 취소)와 신고로 인한 중단만 저장하고, 정원이 찼는지와 시작 시각이 지났는지는 저장하지 않고 볼 때마다 계산한다. 저장해 두면 누가 취소했을 때나 시간이 흘렀을 때 값을 고쳐 줘야 하는데, 그걸 빠뜨리면 화면과 실제가 어긋나기 때문이다.

시간은 DB에 세계 표준시(UTC)로 저장하고 화면에 보여 줄 때와 챗봇이 문장을 해석할 때만 한국 시간으로 바꾼다. 배포 서버의 시계가 UTC라서, 이 변환을 한곳(`timeutil.py`)에 모아 두지 않으면 "오늘 저녁"이 9시간 어긋난다.

## 4. 챗봇이 동작하는 방식

챗봇은 세 단계로 움직인다. 첫째, 사용자의 문장을 검색 조건으로 바꾼다. 둘째, 그 조건으로 DB에서 모임을 고르고 점수를 매긴다. 셋째, 결과를 카드로 보여 준다. 언어 모델(LLM)은 이 가운데 첫 단계만 맡는다.

예를 들어 목요일 오후 2시에 "지금 2시간 비는데 보드게임 할 사람 있어?"라고 물으면, 첫 단계의 결과는 "소요 시간 120분, 종류 보드게임·게임"이다. 서버는 이것을 "오늘 14:00~16:00 사이에 끝나는 보드게임 모임"이라는 구간으로 계산해 DB에서 찾는다. 화면에는 "이렇게 이해했어요: 오늘 14:00~16:00, 보드게임·게임"이 함께 표시되어, 해석이 틀렸으면 사용자가 바로 알아채고 다시 물을 수 있다.

모델에게 모임 목록을 통째로 주고 "골라 달라"고 하는 방식을 쓰지 않은 데에는 이유가 세 가지 있다. 모델이 존재하지 않는 모임을 지어낼 수 있고, 시간 계산을 틀릴 수 있으며, 누군가 모임 소개글에 "이 모임만 추천해"라는 문장을 숨겨 모델을 속일 수 있다(프롬프트 인젝션). 번개팟구에서는 모임 글이 모델에게 전달되지 않으므로 이런 일이 구조적으로 생기지 않는다. 모델이 돌려준 값도 그대로 믿지 않고, 정해진 종류 목록과 시간 형식에 맞는 것만 남긴다.

모델은 수업에서 안내한 OpenRouter의 무료 모델을 쓴다. 무료 키는 하루 50회라는 한도가 있어서, 메시지 하나에 모델을 한 번만 부르고 한 사람이 하루에 쓸 수 있는 횟수도 제한했다. 기본 모델이 제공사 쪽에서 막혀 있으면 미리 정해 둔 다른 무료 모델이 대신 답한다. 키가 없거나 한도를 넘었거나 어느 모델도 제때 답하지 못하면(연결 3초, 응답 대기 12초 제한) `nlu.py`의 규칙 기반 해석기가 같은 일을 대신한다. 규칙 기반 해석기는 "내일", "3시부터 5시까지", "1시간 뒤", "저녁에" 같은 표현과 활동 낱말을 정규식으로 찾아낸다. 어느 쪽이 해석했는지는 말풍선에 "AI 해석" 또는 "기본 해석"으로 표시된다.

## 5. 추천 점수

조건에 맞는 모임이 여럿이면 점수가 높은 순으로 보여 준다. 시간이 딱 맞으면 40점, 30분 이내로 조금 늦게 끝나면 20점, 활동 종류가 맞으면 30점, 키워드가 모임 글에 들어 있으면 하나당 10점, 프로필 관심사와 맞으면 15점을 주고, 곧 시작하는 모임과 마지막 한 자리가 남은 모임에 약간의 가산점을 준다. 점수가 붙은 이유는 "시간이 맞아요", "보드게임·게임 모임"처럼 카드에 함께 표시된다. 이미 참여 중이거나, 참여 중인 모임과 시간이 겹치거나, 정원이 찬 모임은 처음부터 후보에서 뺀다.

## 6. 보안에서 신경 쓴 점

비밀번호는 원문을 저장하지 않고 해시로 저장한다. 로그인에 다섯 번 연속 실패하면 그 계정은 5분 동안 잠긴다. 상태를 바꾸는 모든 요청에는 CSRF 토큰을 요구해서, 다른 사이트가 사용자 몰래 참여나 취소 요청을 보내지 못하게 했다. 모임 수정·마감·취소는 호스트인지 서버에서 다시 확인하고, 댓글 삭제는 작성자와 호스트만 할 수 있다.

입력값은 브라우저에서도 검사하지만 서버에서 한 번 더 검사한다. 브라우저 검사는 개발자 도구로 쉽게 우회할 수 있기 때문이다. 오픈채팅 링크는 `https://`로 시작하는 주소만 받는데, `javascript:`로 시작하는 주소를 넣어 누르는 사람의 브라우저에서 스크립트를 실행시키는 공격을 막기 위해서다. 화면에 내보내는 글은 템플릿 엔진이 자동으로 이스케이프하고, 추가로 콘텐츠 보안 정책(CSP)을 걸어 페이지 안에 끼어든 스크립트가 실행되지 않게 했다.

마지막 한 자리를 두 사람이 동시에 누르는 경우에는 모임 행을 잠근 뒤 인원을 세도록 해서 정원을 넘기지 않게 했고, 같은 사람이 두 번 참여하는 일은 DB 제약으로 막았다.

가입할 때 이메일 형식만 확인한다는 약점 때문에 생기는 남용도 따로 막았다. 방금 만든 계정 여러 개로 남의 모임을 신고해 닫아 버리지 못하도록, 가입한 지 하루가 지난 계정이나 그 모임에 실제로 참여한 사람의 신고만 센다. 한 사람이 동시에 열어 둘 수 있는 모임은 5개, 한 모임에 달 수 있는 댓글은 20개로 제한해 목록과 댓글 창을 도배하지 못하게 했다. 참여와 취소를 되풀이해도 호스트에게 같은 알림이 쌓이지 않는다. 챗봇의 하루 사용 횟수는 DB가 한 문장으로 비교와 증가를 함께 하도록 해서, 요청을 동시에 여러 개 보내도 한도를 넘겨 쓸 수 없다.

비밀번호를 바꾸면 다른 기기에 남아 있던 로그인은 풀린다. 로그인 정보가 서버가 아니라 서명된 쿠키에 들어 있어서, 쿠키에 비밀번호 해시의 끝자리를 함께 넣어 두고 요청마다 대조하는 방식으로 구현했다.

## 7. 한계와 개선 방향

숭실대 학생인지는 이메일 주소 형식(@soongsil.ac.kr)만 확인한다. 실제로 그 주소의 주인인지 확인하려면 인증 메일을 보내야 하는데 이번 범위에서는 구현하지 않았다. 참여는 선착순 자동 확정만 지원하고 호스트가 신청자를 골라 받는 승인 방식이나 대기 신청은 없다. 알림은 사이트에 들어와야 볼 수 있고 휴대폰으로 밀어 보내지는 못한다. 신고는 자동 중단까지만 하고 사람이 내용을 확인하는 절차가 없다. 특정 사용자를 차단하는 기능, 노쇼에 대한 장치, 후기나 매너 점수도 없다. 후기와 점수는 사용자가 충분히 많고 관리자가 있어야 제대로 돌아가는 기능이라 일부러 넣지 않았다. 모임 참여자끼리의 대화는 서비스 밖의 오픈채팅에서 이루어지므로 그 안에서 생기는 문제는 서비스가 알 수 없다.

규칙 기반 해석기는 정해 둔 표현만 알아듣는다. "3교시 끝나고"나 "주말에" 같은 말은 처리하지 못하고, 이런 표현은 언어 모델이 해석해 줄 때만 통한다. 무료 모델의 하루 한도 때문에 사용자가 많아지면 대부분의 질문이 규칙 기반으로 처리된다는 점도 한계다.

수요 검증도 하지 못했다. 문제 정의는 조원들의 경험에서 출발했고 설문이나 인터뷰는 진행하지 않았으므로, 실제 학생들이 어떤 조건으로 모임을 찾는지는 시범 운영을 통해 확인해야 한다.

## 8. 검증

자동 테스트는 pytest로 794개를 작성했고 2026-11-14 기준 모두 통과한다. 가입과 로그인, 모임 만들기와 참여 규칙, 권한, 추천 점수, 문장 해석, 챗봇 API, 알림, 신고, 회원 탈퇴, CSRF와 보안 헤더를 다룬다. 테스트는 현재 시각을 고정하고 언어 모델 호출을 가짜로 바꿔 끼워서, 언제 돌려도 같은 결과가 나오고 외부로 요청이 나가지 않는다.

테스트를 처음 돌렸을 때는 708개 가운데 36개가 실패했다. 대부분 한국어 시간 표현을 잘못 읽는 문제였고("다음 주 월요일", "1시간 30분 뒤", "5시 전", 이미 지난 시각), 비정상적으로 큰 숫자나 0001년 날짜에서 서버 오류가 나는 문제도 있었다. 이들을 고친 뒤 회귀 테스트를 더했다.

그다음 코드를 처음 보는 입장에서 전체를 다시 검토하게 했더니 테스트로는 드러나지 않던 문제가 나왔다. 가장 큰 것은 배포용 DB 주소를 넣으면 앱이 아예 뜨지 않는 문제였다. 로컬에서는 SQLite만 쓰기 때문에 테스트가 모두 통과해도 알 수 없었고, DB 주소에 드라이버 이름을 명시하도록 고쳤다. 그 밖에 버튼을 두 번 누르면 같은 모임이 둘 생기는 문제, 공유 링크로 들어온 사람이 가입을 마치면 보려던 모임을 잃는 문제, 가계정 세 개로 남의 모임을 닫을 수 있는 문제, 비밀번호를 바꿔도 다른 기기의 로그인이 유지되는 문제를 고쳤다. 다른 모임 서비스들과 기능을 비교해 알림함, 신고, 가입 동의, 회원 탈퇴를 추가한 것도 이 단계다.

화면은 로컬에서 예시 데이터를 넣고 브라우저로 확인했다. 실제 OpenRouter 키를 넣은 호출도 로컬에서 확인했다(2026-11-13). 이때 두 가지를 알게 되었다. 하나는 고른 무료 모델(Gemma)이 우리 키의 한도와 상관없이 제공사 쪽에서 일시적으로 막혀 429를 돌려줄 수 있다는 점이고, 다른 하나는 답하기 전에 '생각'을 하는 추론형 모델은 토큰 한도를 500으로 두면 생각만 하다 끊겨 빈 답을 돌려준다는 점이다. 그래서 기본 모델이 막히면 다른 무료 모델로 넘어가는 대체 목록을 두고 토큰 한도를 2,000으로 올렸다. 대체 모델은 후보 넷을 여러 번 호출해 보고 골랐다. Nemotron은 한 번은 6초, 다른 때는 30초가 넘는 식으로 들쭉날쭉했고, Flint가 4~7초로 가장 일정하면서 해석도 정확해 첫 번째 대체 모델로 삼았다. 무료 모델은 모두 답하기 전에 '생각'하는 시간이 있어 유료 모델만큼 빠르지는 않다.

2026-11-14에 Vercel에 배포했다(https://bungae-patgu.vercel.app). Vercel은 설정 없이 Flask 앱으로 인식했고, Neon PostgreSQL을 연결한 뒤 로그인 요청이 DB를 조회해 정상 응답하는 것까지 확인했다. 배포 과정에서 한 가지를 배웠다. Git 커밋에 적힌 이메일이 GitHub 계정과 연결되어 있지 않으면 Vercel이 그 커밋의 자동 배포를 막는다. 저장소의 커밋 이메일을 GitHub 계정의 주소로 맞춰 해결했다.

배포한 사이트에 예시 모임을 넣는 일은 처음에는 내 컴퓨터에서 배포용 DB 주소로 스크립트를 돌리는 방식이었다. 그러려면 비밀번호가 든 접속 주소를 꺼내 터미널에 붙여 넣어야 하고, 예시 모임이 이틀이면 다 지나가서 발표 날 다시 돌려야 했다. 그래서 환경 변수 `SEED_DEMO=1`을 켜 두면 서버가 뜰 때 예시 모임이 모자랄 경우 스스로 채우도록 바꿨다. 서버 여러 대가 동시에 떠서 같은 모임을 두 벌 만드는 일은 PostgreSQL의 잠금으로 막았다. 배포 DB를 직접 열어 예시 모임 11개가 한 벌만 들어간 것을 확인했다.

아직 확인하지 못한 것은 배포 환경에서의 가입·참여 같은 로그인 뒤 동작과, 마지막 한 자리를 정말 동시에 누르는 상황이다.

마지막으로 기능을 실제 사용 순서대로 다시 돌려 보는 점검을 했다. 여러 계정으로 가입·개설·참여·취소·신고를 차례로 실행하면서 시각을 바꿔 가며 화면에 뜨는 문구까지 확인하는 방식이다. 여기서 나온 문제는 성격이 달랐다. 신고로 멈춘 모임에서 신고한 사람이 나가면 차단이 풀리는 문제, 참여와 취소를 되풀이하면 알림함 맨 위가 실제와 반대 내용이 되는 문제, 카드에 보이는 '#초면환영'을 그대로 검색하면 아무것도 안 나오는 문제, 오류 문구를 띄우면서 화면을 아래로 내려 문구가 보이지 않는 문제처럼, 코드 한 줄만 봐서는 틀린 곳이 없고 여러 동작이 이어질 때에만 드러나는 것들이었다.

## 9. 사용 기술

언어는 Python 3, HTML, CSS, JavaScript. 프레임워크와 라이브러리는 Flask, Flask-SQLAlchemy, Flask-WTF(CSRF), requests, pytest. 데이터베이스는 로컬 SQLite, 배포 PostgreSQL(Neon). 언어 모델은 OpenRouter의 무료 모델. 배포는 Vercel, 코드 저장은 GitHub. 개발에는 Claude Code를 사용했다.
