### 4-3. 화면 구성 / 동작 흐름

화면은 로그인·가입, 홈(모임 목록), 모임 만들기, 모임 상세, 추천(챗봇), 내 모임, 알림함 일곱 가지다.

(이미지: 03_home.jpg, 06_detail_guest.jpg, 08_chat_match.jpg 세 장을 나란히 넣는다)

이용자 흐름

```
[가입·로그인]
      ↓
[홈: 열려 있는 모임 목록 + 나를 위한 추천]
   ↙            ↓               ↘
[만들기]     [검색·필터]      [추천 챗봇에 문장으로 질문]
   ↓            ↓               ↓
[모임 등록]  [모임 상세 확인]  [조건 해석 → 맞는 모임 카드]
   ↓            ↓               ↓ (없으면 대안 또는 '이 조건으로 직접 열기')
[참여자 모집]  [참여 → 선착순 확정] ←┘
      ↘        ↙
   [정원이 차면 자동 마감 → 오픈채팅으로 연락 → 모임]
```

챗봇 내부 흐름

```
사용자 문장
   ↓
① 문장 → 조건(날짜, 시각, 소요 시간, 종류, 키워드)
   · OpenRouter 무료 모델이 해석
   · 키 없음 / 한도 초과 / 응답 지연이면 규칙 기반 해석기로 대체
   ↓
② 서버가 조건 값을 검증(허용된 종류·시간 형식만 통과)
   ↓
③ 서버가 DB에서 열려 있는 모임을 고르고 점수 계산
   ↓
④ "이렇게 이해했어요" + 모임 카드 + 추천 이유 표시
```

언어 모델은 ①에서 문장을 조건으로 바꾸는 일만 한다. 어떤 모임을 추천할지는 서버 코드가 DB에서 직접 고르므로, 모델이 없는 모임을 지어내거나 모임 소개글에 적힌 문장에 휘둘리는 일이 생기지 않는다.

### 4-4. 핵심 코드 설명

**(1) 조건에 맞는 시간인지 판정하는 코드 — bungae/recommend.py**

```python
def time_fit(meeting, cond):
    """('fit' | 'near' | 'miss' | 'none', 설명)"""
    if not cond.has_time:
        return "none", None
    near_reason = None

    if cond.max_duration_min and meeting.duration_min > cond.max_duration_min:
        over = meeting.duration_min - cond.max_duration_min
        if over > NEAR_MINUTES:
            return "miss", None
        near_reason = f"{over}분 더 걸려요"

    if cond.window_start and meeting.start_at < cond.window_start:
        return "miss", None

    if cond.window_end:
        if cond.must_end_in_window:
            over = int((meeting.end_at - cond.window_end).total_seconds() // 60)
            if meeting.start_at >= cond.window_end or over > NEAR_MINUTES:
                return "miss", None
            if over > 0:
                near_reason = f"{over}분 늦게 끝나요"
        elif meeting.start_at >= cond.window_end:
            return "miss", None

    if near_reason:
        return "near", near_reason
    return "fit", "시간이 맞아요"
```

이 코드가 하는 일: 사용자가 말한 시간 구간과 모임 시간을 비교해 "맞음 / 거의 맞음 / 안 맞음"을 가린다. "2시간 비는데"처럼 빈 시간을 말한 경우에는 모임이 그 안에 끝나야 하고, "저녁에"처럼 막연한 시간대를 말한 경우에는 그 안에 시작하기만 하면 된다.

왜 이렇게 만들었나: 처음 기획에는 모임 정보에 시작 시각만 있었는데, 그러면 "2시간 빈다"는 말과 맞춰 볼 수가 없어서 예상 소요 시간을 모임 정보에 추가했다. 또 딱 맞는 모임만 보여 주면 결과가 비기 쉬워서, 30분 이내로 넘치는 모임은 "30분 늦게 끝나요"라는 설명을 붙여 후보로 남겼다. 이 판정은 언어 모델이 아니라 코드가 하므로 같은 질문에는 항상 같은 결과가 나온다.

**(2) 모델의 답을 검증하는 코드 — bungae/nlu.py**

```python
def sanitize_slots(raw, today):

    slots = empty_slots()
    if not isinstance(raw, dict):
        return slots
    ...
    value = raw.get("categories")
    if isinstance(value, list):

    ...

```

이 코드가 하는 일: 언어 모델이 돌려준 JSON에서 날짜, 시각, 소요 시간, 종류, 키워드를 하나씩 꺼내 형식이 맞는 것만 남긴다. 종류는 미리 정한 여덟 가지 안에 있는 것만, 날짜는 오늘부터 14일 안의 것만 통과한다.

왜 이렇게 만들었나: 언어 모델은 가끔 형식을 어기거나 없는 값을 만들어 낸다. 모델의 답을 그대로 DB 검색에 쓰면 오류가 나거나 엉뚱한 결과가 나오므로, 모델을 "믿을 수 없는 외부 입력"으로 취급했다. 같은 이유로 모델에게는 사용자의 문장만 보내고 모임 목록은 보내지 않는다.

## 🔍결론 및 회고

### 6-1. 목표 달성도

2장에서 정한 최종 아이디어는 "호스트가 번개 모임을 만들고 게스트가 참여하는 기능을 기본으로, 원하는 시간과 관심 조건에 맞춰 열려 있는 모임을 추천한다"였다. 모임 생성·참여·자동 마감, 조건 검색, 관심사 기반 추천, 문장으로 묻는 추천 챗봇까지 구현해 기획한 범위는 모두 동작하고, 실제 주소로 배포해 누구나 접속해 볼 수 있다.

처음 정의한 문제 가운데 "현재 참여 가능한 모임의 시간, 인원, 분위기를 한눈에 파악하기 어렵다"는 부분은 목록과 상세 화면, 추천으로 해결했다. 반면 "실제로 함께할 사람을 빠르게 찾게 되는가"는 사용자가 모여야 확인할 수 있는 부분이라 이번 프로젝트에서는 검증하지 못했다.

### 6-2. 한계점과 개선 방향

- 숭실대 학생 인증을 이메일 형식으로만 확인한다. 인증 메일을 보내 실제 소유자인지 확인하는 절차가 필요하다.
- 참여는 선착순 자동 확정만 된다. 호스트가 신청자를 승인하는 방식과 대기 신청을 추가할 수 있다.
- 알림은 사이트에 들어와야 볼 수 있다. 휴대폰 알림이나 메일로 보내 주지는 못한다.
- 참여자끼리의 대화는 서비스 밖 오픈채팅에서 이루어져, 그 안에서 생기는 문제를 서비스가 알 수 없다.
- 무료 언어 모델은 제공사 사정으로 수시로 막히고, 대체 모델이 답할 때는 4~7초가 걸린다. 하루 한도(50회)를 넘으면 규칙 기반 해석으로 처리되는데, 규칙 기반 해석기는 "3교시 끝나고" 같은 표현을 알아듣지 못한다.
- 비밀번호를 잊었을 때 다시 설정하는 기능이 없다.
- 신고는 3명이 쌓이면 모집을 자동으로 멈추는 데까지만 한다. 사람이 내용을 확인하는 절차, 특정 사용자 차단, 노쇼 방지 장치가 없다.
- 설문이나 인터뷰로 수요를 확인하지 못했다. 시범 운영으로 실제 사용 조건을 조사할 필요가 있다.

## 🎤 7. 발표

발표 순서: 문제 상황 → 배포 사이트에서 번개 열기 → 다른 계정으로 참여해 정원 마감 확인 → 챗봇에 "지금 2시간 비는데 보드게임 할 사람 있어?" 질문 → "이렇게 이해했어요"와 추천 이유 설명 → 맞는 모임이 없는 질문으로 대안과 직접 열기 버튼 시연 → 모델이 아니라 서버가 모임을 고르는 구조 설명 → 한계와 개선 방향.

예상 질문과 답

- 왜 모델에게 모임을 직접 고르게 하지 않았는가: 모델이 없는 모임을 지어내거나 시간 계산을 틀릴 수 있고, 모임 소개글에 적힌 문장에 휘둘릴 수 있다. 그래서 모델은 문장을 조건으로 바꾸는 일만 하고 모임은 서버가 DB에서 고른다.
- 무료 한도를 넘으면 어떻게 되는가: 규칙 기반 해석기로 넘어가 같은 요청 안에서 답한다.
- 두 명이 동시에 마지막 자리를 누르면 어떻게 되는가: 모임 행을 잠근 뒤 인원을 세므로 한 명만 참여되고 다른 한 명은 마감 안내를 받는다.
